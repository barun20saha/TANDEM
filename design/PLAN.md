# Tandem WS3 UI Redesign Plan

## 1. Critique of Current WS2 UI (Why Redesign)
While WS2 eliminated mock data and wired every screen to `tandemd`, a visual and structural review reveals five defects against a precision desktop/mobile utility aesthetic:
1. **Broken Dark Mode:** Components (`DeviceRow`, `FolderRow`, `BannerNotification`, `TandemButton`, `ConfirmDialog`, `HomeShell`) read `TandemTokens.color_surface` / `color_text` directly instead of resolving `Theme.of(context).brightness`, causing light-on-light or unadapted backgrounds when `ThemeMode.dark` is active.
2. **Unbounded Desktop Layouts & AppBar Clutter:** Desktop (`HomeShell`) opens without a persistent navigation rail, hides Send / Health / Activity / Settings behind tiny AppBar icon buttons, and lets `ListView` screens (`FolderDetail`, `LinkStatus`, `Settings`, `HealthCheck`) stretch edge-to-edge across 1920px viewports.
3. **Middle-Dot & Card Noise:** Subtitles concatenate unrelated metadata with `•` (`files • size • State: ...`), and secondary sections wrap every group in bordered rounded boxes instead of using clean hairline rules and structured tables.
4. **Undersized Body Text:** Default `text_md` (`14px`) feels cramped for dense operational metadata and path/error text on desktop (`15px` target) and mobile (`16px` target).
5. **Modal-Heavy Workflows:** `SendScreen` forces a modal dialog even on wide viewports instead of providing a direct inline workspace panel.

---

## 2. Target Visual Direction & Design System Revisions
- **Aesthetic:** Precision Local-First Engineering Tool. Calm, high-contrast neutral surfaces, crisp `0.5px` borders, `tabular-nums` alignment on all speeds/sizes/codes, and **`LinkLine`** as the singular visual signature showing `direct-local` (solid blue), `direct-internet` (dashed blue), `relayed` (dotted amber), `connecting` (dashed border), and `offline` (transparent).
- **Theme-Aware Token Helpers (`app/lib/theme/tokens.dart`):**
  Keep every existing static constant (`color_link_direct`, `color_link_relay`, `space_*`, `radius_*`) intact for backwards compatibility with `tokens_test.dart`, and add context-aware accessors generated by `design/generate_tokens.py`:
  - `TandemTokens.ground(context)`, `surface(context)`, `border(context)`, `text(context)`, `mutedText(context)`
  - `TandemTokens.linkDirect(context)`, `linkRelay(context)`, `linkRelayText(context)`, `ok(context)`, `danger(context)`, `onPrimary(context)`
  - `TandemTokens.bodyText(context)` (`15.0px` when viewport width `>= 768px`, `16.0px` on mobile `< 768px`).
- **Workspace Framing Rules:**
  - Desktop (`>= 1024px`): Two-region shell — a fixed `280px` left navigation + live peer rail (`Folders`, `Send`, `Devices`, `Activity`, `Health Check`, `Settings` + live paired/nearby peer rows with inline `LinkLine`) separated by a `0.5px` hairline border from the primary canvas.
  - Inside the primary canvas, all scrollable views align left (`Alignment.topLeft`) inside `ConstrainedBox(maxWidth: 960.0)` with consistent horizontal padding (`24px` desktop, `16px` mobile).
  - Compact/Mobile (`< 1024px`): Top header with screen title + health/settings shortcuts and bottom navigation bar (`Folders`, `Send`, `Devices`, `Activity`) with minimum `48dp` interactive targets.
- **Anti-Clutter Rules:**
  - Zero decorative uppercase eyebrows above headings.
  - Zero middle-dot (`•`) string concatenation; use structured columns, aligned metadata cells, or spaced inline tags.
  - Zero redundant wrapper cards around lists/tables; render flat rows separated by `0.5px` hairline dividers and reserve bordered panels strictly for distinct focused tools (Pairing QR/code panel, Send composer, Confirmation modal).

## 3. Screen-by-Screen Redesign Plan (`S1`–`S11`)
- **S1 (`FirstRunScreen`):** Left-aligned `640px` onboarding view inside `color-ground` showing local device name/ID in monospace tabular strip, a crisp two-row Send vs. Sync distinction table, single primary `"Pair device"` action button, and honest status note if daemon is still discovering peers.
- **S2 (`FoldersScreen`):** Top action bar (`Folders` + live count + `"Choose folder"` button) above a dense column-aligned table on wide screens (`Folder & Path` | `Mode` | `Size` | `Peers` | `State`) and compact two-line `FolderRow`s on narrow viewports.
- **S3 (`FolderDetailScreen`):** Header with path + live `Pause`/`Resume` control + structured status summary grid + flat segmented mode picker (`Send & Receive` / `Send only` / `Receive only`) + `.tandem-trash` table (`Path`, `Deleted`, `Size`, `Restore`) + destructive `"Stop syncing"` confirmation.
- **S4 (`SendScreen`):** Inline Send composer (paired peer selector + multi-line file path / file picker input + `"Send files"` button) above active & completed `TransferRow` items with live speed (`tabularFigures`), bytes remaining, and physical link/interface tag.
- **S5 (`DevicesScreen`):** Dedicated full-pane device manager listing `This device` identity/port strip, paired peers with interactive `LinkLine` indicators + live throughput, and nearby discovered unpaired peers with `"Pair"` action.
- **S6 (`LinkStatusScreen`):** Peer topology header showing `Local <-> LinkLine <-> Peer` with speed readout, honest relay banner (`Through a relay (slower)`) whenever `linkState == relayed`, tabular metric grid (`Upload`, `Download`, `Addresses`, `Last seen`, `Engine/Port/Firewall`), and `"Unpair device"` confirmation.
- **S7 (`PairingScreen`):** Asymmetric split on wide screens (left: `PairingPanel` with QR payload + spaced 6-digit tabular code; right: discovered peer quick-fill + ID/code confirmation form), stacked vertically on mobile.
- **S8 (`NoInternetHelperScreen`):** Preserved Flows B–E offline transfer guide using theme-aware tokens and clean step rows (no `•` separators).
- **S9 (`HealthCheckScreen`):** Banner summary + tabular diagnostic checklist (`Engine`, `Sync Port`, `Local Discovery`, `Firewall` with copyable remediation command, `Storage`, `File Watchers`) + `"Run diagnostics again"` trigger.
- **S10 (`SettingsScreen`):** Structured daemon configuration & runtime identity table (`Device Name`, `Device ID`, `Version`, `State`, `Sync Port`, `Discovery Port`, `Internet Reachable`) with explicit refresh.
- **S11 (`ActivityScreen`):** Chronological table of ephemeral Send sessions (`TransferRow`) and live daemon SSE event rows without borders/shadows.

## 4. Plan Review & Recorded Revisions (Before Implementation)
- **Revision 1 (Keep Token & Component Compatibility):** Reviewed `app/test/tokens_test.dart` and `app/test/components/*_test.dart`. Keeping static constants (`TandemTokens.color_*`, `space_*`, `radius_*`) while adding theme-aware instance/static methods (`TandemTokens.surface(context)`) preserves 100% compatibility with existing component tests while fixing dark mode across every widget.
- **Revision 2 (Navigable Rail vs. Split-Only):** In WS2, clicking a device in the desktop rail hid `FoldersScreen` inside the same right pane with no clear way back to Folders/Send/Activity/Health/Settings other than tiny AppBar icons. Revision: make the desktop left rail explicitly hold both the 6 primary route destinations **and** the live `Peers` list, with breadcrumb/close or route selection switching cleanly in the `960px` right workspace.
- **Revision 3 (Keyboard & Focus Traversal):** Wrap custom interactive rows (`FolderRow`, `DeviceRow`, rail items) with `Focus` / `InkWell` focus highlights in `color_link_direct` and verify Tab + Enter/Space navigation in widget tests.
- **Revision 4 (Deterministic Visual Evidence Across 3 States & 6 Viewports):** Build an automated Flutter rasterizer test (`app/test/screenshots_ws3_test.dart`) rendering real `TandemApp` and detail flows into PNGs at `1920x1080`, `1280x800`, and `390x844` in both Light and Dark themes for:
  1. Empty daemon state
  2. Two paired syncing instances (`direct-local`, `relayed`, syncing folder, active send transfer)
  3. Failing link / error state (`401`/`unreachable`, offline peer, firewall warning, disk-full folder error)
  Save PNGs under `docs/evidence/screenshots/`, inspect them visually using `read_file`, log top 3 findings per screen in `design/CRITIQUE.md`, fix them, and re-capture.
